# 터미널 발송·송장 대사

## 배경

가족이 운영하는 경남 통영 수산물 B2B 사업의 전체 프로세스(D-1 주문 수집 → D-day 경매/재고 확보 → 작업장 포장 → 터미널 발송 → 정산) 중, 8단계(터미널 발송·송장 대사)를 첫 자동화 대상으로 선정했다. 이 기능은 앞으로 확장될 `age-seafood` 수산물 B2B 운영 시스템의 첫 모듈이다.

### 현재 방식과 문제
- 포장된 박스를 도착터미널별로 모아 차량으로 통영종합버스터미널로 이동, 박스 뚜껑 상단 라벨을 폰 카메라로 촬영해 카카오톡으로 공유
- 버스회사로부터 종이 송장(버스회사명·차량번호·적재 수량·출도착시간·도착지)을 수령
- 대표가 버스 송장 수량, 박스 라벨, 주문 리스트(현재 작업장 화이트보드에 손으로 기재)를 눈으로 대조
- 문제: (1) 수량 불일치를 늦게 발견하고 원인 파악에 시간이 걸림, (2) 대사 자체가 오래 걸림, (3) 기록이 카카오톡 사진첩에만 남아 추적 불가

## 목표

**성공 지표**: 버스 출발 전에 터미널별 수량 불일치를 발견하고, 언제·어떤 터미널에서 무엇이 있었는지 기록이 남아 사후 추적이 가능하다.

부가적으로 대사 소요 시간도 현재 대비 단축되는 것을 목표로 하되, 1차 지표는 "제때 발견 + 기록 보존"이다.

## 안 만들 것 (Non-goals)

- 버스회사 시스템과의 자동 연동(API) — 종이 송장 내용은 사람이 앱에 직접 입력
- 정산·영수증 발행 기능(9단계) — 이번 범위에 포함하지 않음
- 라벨 글자 OCR 자동 인식 — 색연필 손글씨가 섞여 있어 정확도가 낮으므로, 사람이 사진을 보고 직접 탭하여 체크하는 방식으로 시작
- 오프라인 모드 — 터미널 현장에 와이파이/LTE가 있어 v1에서는 불필요
- D-1 주문 수집 단계와의 자동 연동 — v1의 주문 리스트는 발송 직전 대표(또는 가족)가 직접 입력

## 사용자 시나리오

1. 발송 직전, 대표(또는 가족 구성원)가 웹앱에 오늘의 주문 리스트를 입력한다: 터미널명, 고객사명, 박스 수량(터미널·고객사 단위).
2. 박스를 터미널별로 모아 차량에 싣고 통영종합버스터미널로 이동한다.
3. 현장에서 웹앱 내장 카메라로 박스 뚜껑 상단 라벨을 촬영한다. 사진은 해당 터미널/주문건에 자동으로 연결되어 저장된다(폰 갤러리·카카오톡을 거치지 않음).
4. 버스별로 종이 송장을 받으면, 앱에 해당 버스 편의 송장 정보(버스회사명, 차량번호, 적재 수량, 도착지, 출/도착시간)를 입력한다.
5. 앱은 그 버스 편에 해당하는 주문 리스트 항목(고객사별 박스 수량)을 체크리스트로 보여준다. 사용자는 촬영된 라벨 사진을 보면서 고객사 항목을 하나씩 탭하여 체크한다.
6. 체크된 수량 합계와 송장 수량이 다르면 화면에 "불일치"로 표시한다. 처리(재확인, 고객사 연락 등)는 사용자가 직접 판단한다.
7. 모든 버스 편의 대사 결과와 각 항목을 누가 체크했는지는 기록으로 남아 나중에 조회할 수 있다.

## 요구사항

### 데이터 모델 (개념 수준)
- **주문 리스트 항목**: 터미널명, 고객사명, 박스 수량, (날짜)
- **버스 편(송장)**: 터미널, 버스회사명, 차량번호, 적재 수량, 출발/도착시간, 도착지
- **라벨 사진**: 촬영 시각, 촬영자, 연결된 터미널/주문건(선택적으로 고객사)
- **대사 기록**: 버스 편 기준, 체크된 고객사·수량, 체크한 사용자, 불일치 여부, 시각

### 기능
- 주문 리스트 입력 (터미널·고객사·박스 수량)
- 웹앱 내장 카메라로 라벨 사진 촬영 및 터미널/주문건 연결 저장
- 버스 편(송장) 정보 입력
- 버스 편 단위 대사 체크리스트 (고객사별 탭 체크, 사진 열람하며 진행)
- 불일치 표시 (체크 합계 ≠ 송장 수량)
- 사용자별 로그인 및 "누가 체크했는지" 기록
- 과거 대사 기록 조회

### 인증
- 가족 구성원별 개별 계정 (이메일·비밀번호 로그인). 역할 구분(관리자/작업자 등)은 v1에서는 불필요 — 필요해지면 추가.

## 엣지 케이스와 실패 시 동작

- **한 터미널에 여러 버스 편이 갈 때**: 대사는 버스 편(송장) 단위로 각각 수행한다. 터미널 합계가 아니라 편별로 불일치를 판단한다.
- **한 고객사에 박스가 2개 이상일 때**: 박스 개별 번호(색연필 표기)는 v1에서 추적하지 않는다. 고객사 단위로 목표 박스 수 대비 체크된 개수만 비교한다.
- **수량 불일치 발생 시**: 화면에 표시만 하고 자동 조치(고객사 알림 등)는 하지 않는다.
- **네트워크 불안정**: v1에서는 대응하지 않는다(현장 연결 충분). 문제가 반복되면 로컬 저장 후 동기화 방식으로 재검토.
- **주문 리스트가 발송 직전에 변경될 때**: 재입력/수정 가능해야 한다 (삭제·추가·수량 변경).

## 완료 기준 (체크리스트)

- [ ] 대표(또는 가족)가 웹앱에서 터미널·고객사·박스 수량으로 주문 리스트를 입력할 수 있다
- [ ] 현장에서 웹앱 내장 카메라로 라벨 사진을 찍고 해당 터미널/주문건에 저장할 수 있다
- [ ] 버스 편(송장) 정보를 입력할 수 있다
- [ ] 버스 편별로 고객사 체크리스트를 보고 사진을 참고하며 탭으로 체크할 수 있다
- [ ] 체크 합계와 송장 수량이 다르면 불일치가 화면에 표시된다
- [ ] 가족 구성원이 각자 계정으로 로그인하고, 누가 체크했는지 기록에 남는다
- [ ] 과거 대사 기록을 날짜/터미널로 조회할 수 있다
- [ ] 실제 발송일에 현장에서 1회 이상 테스트 완료

## 미결 질문

- 정식 배포 시 도메인·인프라 비용을 누가 어떻게 부담할지 (Vercel/Supabase 무료 티어로 v1은 충분할 것으로 예상되나 확인 필요)
- 가족 구성원 계정 수와 역할 구분이 앞으로도 필요 없을지, 사업 확장 시 재검토 필요
- 라벨 사진의 장기 보관 기간·용량 정책 (Supabase Storage 무료 티어 한도 고려)
