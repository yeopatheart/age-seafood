# age-seafood 실사용 전 점검 (2026-09-28)

현장 작업자(사진 촬영 담당)와 대표(정산·확정 담당) 두 입장에서 앱을 직접 써보고 코드를 검토해서 찾은 문제들이다. 실제 업무 투입 전 확인이 필요한 순서대로 정리했다.

## 요약

- **🔴 심각 4건**: 오분류 수정 불가, 확정 후 수정 불가, 수량 불일치 확정 방지 없음, 동시성 버그(같은 터미널 중복 생성 가능)
- **🟡 중간 5건**: 업로드 중단 시 사진 유실 위험, 라이브 카메라 실기기 미검증, 실패 사진 특정 불가, 중복 업로드 방지 없음, 세션 만료 안내 불친절
- **🟢 사용성 5건**: 탭 타겟 축소, 불일치 정도 안 보임, 박스 수량 수정 UI 없음, 이력 탭 터미널 검색 없음, 사진 확대 화면 핀치줌 불가
- **🔵 운영 전 미검증 3건**: PWA 실기기 설치, 다중 사용자 동시 접속 체감 성능, Anthropic 결제수단 연결 여부

## 🔴 심각 — 실제 업무에 바로 영향

### 1. 사진 한 장이 잘못 분류돼도 고칠 방법이 없다
지난 라운드에서 "다른 그룹으로 이동" 드롭다운을 없애고 좌우 넘기기로 바꿨다. 그 결과 라벨 사진 한 장이 엉뚱한 터미널로 자동분류돼도 **개별적으로 옮길 수단이 전혀 없다.** 유일한 해결책은 그 그룹 전체를 삭제하고 처음부터 다시 찍는 것인데, 그러면 같이 있던 정상 사진들까지 다 날아간다.

OCR 인식률을 이제 막 모니터링하기 시작하는 단계라는 걸 감안하면, 오분류는 반드시 나올 텐데 그걸 가볍게 고칠 방법이 없는 건 실사용 첫 주부터 불편함으로 드러날 가능성이 높다.
→ **권장**: 확대 화면에 "다른 그룹으로 옮기기" 같은 가벼운 수정 수단을 다시 고려 (드롭다운이 아니어도, 확대 화면의 별도 버튼 등으로).

### 2. 확정(이력으로 이동) 이후에는 아무것도 되돌릴 수 없다
이력 탭은 완전히 읽기 전용이다 — 삭제 버튼도, 수정 버튼도 없다. 터미널명·출발시간·박스 수량이 잘못 확정된 걸 나중에(예: 정산하다가) 알아채도 고칠 방법이 없다.
→ **권장**: 최소한 이력에서도 삭제는 가능하게 하거나, 관리자가 다시 열어 고칠 수 있는 경로 필요.

### 3. 박스 수량이 "불일치"여도 확정을 막지 않는다
확인 탭에서 수량이 안 맞으면 빨간 "불일치" 뱃지가 뜨지만, 체크박스 선택과 확정하기 버튼은 그대로 눌린다. 이 앱을 만든 핵심 이유가 "발송 물량 대사"인데, 불일치 상태로 조용히 확정되는 걸 막거나 최소한 한 번 더 확인시키는 절차가 없다.
→ **권장**: 불일치 그룹을 선택해서 확정하려 할 때 "수량이 안 맞는데 그대로 확정할까요?" 확인 절차 추가.

### 4. 같은 터미널·같은 날짜 그룹이 동시에 두 개 생길 수 있다 (동시성 버그)
`bus_trips` 테이블에 `(trip_date, terminal_name)` 유니크 제약이 없다. `findOrCreateTrip`(`src/app/actions.ts`)은 "select 해보고 없으면 insert"하는 방식인데, 가족 여러 명이 각자 폰으로 **동시에** 같은 터미널로 가는 첫 사진을 업로드하면 두 요청이 거의 동시에 "없음"을 확인하고 각자 새 그룹을 만들어버릴 수 있다. 흔하진 않지만, 발생하면 같은 터미널 사진이 두 그룹으로 쪼개져서 박스 수량 대사가 틀어진다. 이건 "여러 사람이 하루 종일 계속 업로드"가 핵심 시나리오인 이 앱에서 실제로 일어날 수 있는 문제다.
→ **권장**: DB에 `(trip_date, terminal_name)` 유니크 인덱스 추가 + 충돌 시 재조회하는 로직.

## 🟡 중간 — 특정 상황에서 불편하거나 데이터가 샐 수 있음

### 5. 업로드 도중 화면을 벗어나면 사진이 붕 뜬 채 사라진다
라벨/버스송장 사진은 "N장을 다 올리고 → 한 번에 커밋"하는 구조다. N장을 업로드하는 도중 전화가 오거나, 오래된 폰이 메모리 부족으로 탭을 정리하면 **이미 스토리지에는 올라갔지만 배송 기록에는 안 남는** 사진이 생긴다. 사용자는 찍었다고 생각하지만 앱 어디에도 안 보인다.
→ **권장**: 사진 하나 업로드가 끝날 때마다 바로 커밋하도록 구조를 좁히거나, 최소한 업로드 중 이탈 방지 안내.

### 6. 연속촬영(라이브 카메라)이 실기기에서 한 번도 검증되지 않았다
이 세션의 브라우저 자동화 환경은 카메라 권한이 항상 차단돼서, `getUserMedia` 기반 라이브 카메라 화면은 **매번 "카메라를 열 수 없습니다" 폴백 경로로만** 테스트됐다. 실제 아이폰 Safari·안드로이드 Chrome에서 라이브 화면, 연속 셔터, 갤러리 버튼이 정말 잘 동작하는지 아직 아무도 확인한 적이 없다 — 이 앱의 핵심 기능인데도.
→ **권장**: 실제 기기 2종(iOS, Android) 각 1회 이상 라이브 카메라 경로 직접 테스트 필요.

### 7. 일부 사진 업로드가 실패해도 "어떤 사진"인지 알려주지 않는다
여러 장 중 일부만 실패하면 "일부 사진 업로드에 실패했습니다. 다시 시도해주세요"라고만 뜬다. 몇 번째 사진인지, 몇 장이 이미 성공했는지 모른다. "다시 시도"하려면 촬영부터 다시 해야 하는데, 이미 성공한 사진까지 또 올라가 중복이 생길 수 있다.

### 8. 중복 사진을 막는 장치가 없다
같은 사진을 실수로 두 번 선택하거나 갤러리에서 같은 파일을 또 고르면 그대로 중복 업로드된다. 택배송장 장수가 부풀려져서 버스송장 수량과의 "일치/불일치" 판정이 틀어질 수 있다.

### 9. 세션이 끊겼을 때 안내가 불친절하다
자동 로그인이 유지되도록 설계돼 있지만, 혹시 세션이 만료된 채로 업로드를 시도하면 "저장에 실패했습니다"라고만 뜨고 재로그인이 필요하다는 걸 알려주지 않는다. 노년층 사용자는 이 상황에서 뭘 해야 할지 헷갈릴 수 있다.

## 🟢 사용성 — 쓸 수는 있지만 더 나아질 수 있는 부분

### 10. 확인 탭 카드 헤더가 촘촘해졌다
최근 모바일 폭 넘침을 고치면서 터미널명·출발시간 입력창과 삭제 버튼을 줄였다(높이 44px). 이 프로젝트가 처음부터 지켜온 "60대 이상은 최소 48px 탭 타겟" 기준보다 살짝 작아진 상태다. 특히 삭제는 되돌릴 수 없는 동작이라, 촘촘해진 만큼 오조작 위험이 약간 늘었다.

### 11. "불일치"가 몇 개 차이인지 안 보인다
12개 중 11개(1개 차이)와 12개 중 2개(10개 차이)는 심각도가 완전히 다른데 둘 다 그냥 빨간 "불일치"로만 표시된다. 차이 숫자를 같이 보여주면 담당자가 뭘 먼저 봐야 할지 바로 판단할 수 있다.

### 12. 박스 수량을 사람이 고칠 수 있는 입력창이 없다
출발시간은 확인 탭에서 직접 고칠 수 있는데, 박스 수량은 AI가 잘못 읽어도 고칠 방법이 없다. 손글씨 오독 가능성이 가장 크다고 지목했던 항목인데 정작 수정 수단이 빠져 있다. (예전엔 있었지만 안 쓰는 코드 정리 과정에서 화면 자체가 없어짐 — `confirmInvoiceBoxCount` 참고)

### 13. 이력 탭에서 터미널명으로 찾을 수 없다
날짜는 고를 수 있지만 터미널명 검색이 빠져서, 특정 거래처 기록을 찾으려면 날짜를 하나씩 넘겨봐야 한다.

### 14. 사진 확대 화면에서 더 확대(핀치 줌)할 수 없다
`object-contain`으로 화면 안에 맞춰 보여주기만 해서, 흐릿한 손글씨를 원본 해상도로 더 자세히 보고 싶어도 방법이 없다.
