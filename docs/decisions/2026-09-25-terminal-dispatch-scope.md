# 2026-09-25 터미널 발송·송장 대사 — 범위 결정

## 배경
`age-seafood`(수산물 B2B 운영 시스템)의 첫 자동화 기능으로 9단계 전체 프로세스 중 어디를 먼저 다룰지, 그리고 그 기능의 구체적 방식을 정했다.

## 결정 1: 첫 자동화 대상 = 8단계 (터미널 발송·송장 대사)
- 선택지: 주문 수집·정리(1~5단계) / 작업장 포장 지원(6~7단계) / 터미널 발송·대사(8단계) / 정산·영수증(9단계)
- 선택: 터미널 발송·송장 대사
- 이유: 수량 불일치를 늦게 발견하고, 대사가 오래 걸리고, 기록이 카카오톡 사진첩에만 남는 문제가 가장 급함

## 결정 2: 주문 리스트 디지털 입력 방식
- 선택지: 대표가 발송 직전 직접 입력 / D-1 주문 수집 단계부터 디지털화
- 선택: 발송 직전 직접 입력
- 이유: 범위를 좁게 유지. 주문 수집 단계 디지털화는 별도 기능으로 나중에 다룬다

## 결정 3: 라벨 인식 방식
- 선택지: OCR 자동 인식 / 사람이 사진 보고 직접 탭하여 체크
- 선택: 사람이 직접 탭
- 이유: 스티로폼 박스에 색연필로 쓴 손글씨가 섞여 있어 OCR 정확도가 낮을 것으로 예상. 구현 단순성과 신뢰성 우선

## 결정 4: 라벨 사진 촬영 방식
- 선택지: 웹앱 내장 카메라 직촬 / 폰 카메라로 찍고 앱에 업로드 / 사진 촬영은 자동화 범위 제외
- 선택: 웹앱 내장 카메라 직촬
- 이유: 사진이 해당 터미널/주문건에 자동으로 연결되어 카카오톡·갤러리를 거치지 않고 바로 기록으로 남음. 별도 앱 설치 없이 모바일 브라우저로 가능

## 결정 5: 대사 단위
- 선택지: 버스 편(송장) 단위 / 터미널 전체 합계 단위
- 선택: 버스 편 단위
- 이유: 한 터미널에 여러 버스 편이 나뉘어 갈 수 있고, 송장도 편마다 따로 나오기 때문에 편 단위로 대사해야 정확함

## 결정 6: 인증 방식
- 선택지: 로그인 없음 / 공유 비밀번호 1개 / 개별 계정
- 선택: 가족 구성원별 개별 계정
- 이유: 가족 여러 명이 사용하며, 누가 대사를 체크했는지 기록이 필요함

## 결정 7: 불일치 발생 시 동작
- 선택지: 표시만 함(v1) / 표시 + 메모 입력까지
- 선택: 화면에 "불일치" 표시만, 처리는 사용자가 직접 판단 (메모 등 추가 기록 기능은 v1 범위 밖)
- 이유: 최소 구현으로 시작, 필요성이 확인되면 증분으로 추가

## 결정 8: 오프라인 대응
- 선택지: 로컬 저장 후 동기화 / v1에서는 대응 안 함
- 선택: v1에서는 대응 안 함
- 이유: 통영종합버스터미널 현장에 와이파이·LTE가 충분함을 확인함

## 결정 9: 프로젝트 위치·이름
- 선택: `apps/age-seafood` (제품 레포, 실험이 아님)
- 이유: 실제 운영 중인 사업을 지원하는 시스템이며, 앞으로 다른 단계도 같은 레포에 계속 추가될 예정
